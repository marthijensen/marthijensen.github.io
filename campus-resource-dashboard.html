Overview

Why this project matters

UVU student-facing services support student success, but resource utilization data can be separated by department, service area, or system. This makes it difficult for leadership to quickly see how services are being used across campus.

The proposed Campus Resource Utilization Dashboard would give Student Affairs leadership a centralized way to review usage trends, workload, capacity, peak demand, staffing needs, and possible service gaps.

Business Problem

The current challenge

The main issue is that UVU does not currently have one easily accessible dashboard that standardizes resource utilization information across student-facing services. Departments may track information separately, which can lead to manual reporting, inconsistent definitions, and slower decision-making.

No unified view

Resource usage information may exist, but it is not easily available in one centralized leadership view.

Data access limitations

Real institutional data requires approval, governance review, and privacy consideration before use.

Decision-making impact

Without a dashboard, staffing, funding, service hours, and promotion decisions may rely on disconnected reports.

Proposed Future State

A centralized decision-support dashboard

The future state would allow selected student-facing services to contribute standardized, aggregated utilization data into a shared dashboard. Leadership could compare service demand, usage trends, capacity, and operational patterns across departments.

Change Strategy

Recommended path forward

The recommended approach is not to build a live production dashboard immediately. Instead, the project should start as a proof-of-concept using dummy data, public data, or approved aggregate data.

  1. Prototype and recommendation: Build a dashboard concept and recommendation package using dummy or public data.
  2. Pilot with real data: After approvals, test the dashboard with a small group of services and authorized users.
  3. Full rollout: Expand to all in-scope services with role-based access, benchmarks, and training.

Risks

Important risks and constraints

Data Privacy

Student data must be protected, and any real-data version would need to follow FERPA and institutional governance rules.

Approval Delays

Access to real UVU data could require a long approval process, including IRB and data governance review.

Adoption

Department directors and leaders would need to trust the data, understand the dashboard, and use it consistently.

Metric Context

Numbers should not be shown without context because low usage does not always mean low value or low student need.

Recommendation

Pursue while mitigating risk

The recommendation is to pursue the project carefully by starting with a limited proof-of-concept. This allows the team to show the potential value of a centralized dashboard while avoiding privacy, approval, and governance issues that would come with using real institutional data too early.
